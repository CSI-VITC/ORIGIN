# User Taste
- **Never touch existing content or data when redesigning or transforming an existing site/app.** When asked to "transform" a site, treat the existing copy, headings, CTAs, data arrays, images, and content sections as inviolable — only layer visuals, motion, and chrome on top. Confidence: 0.95
- **Prefers immersive, cinematic, scrollytelling experiences over conventional layouts** when asked for a "masterpiece" — themes like "birth of the universe", "origin of innovation", cosmic/cosmogonic metaphors, and a single dominant thematic color (e.g. orange) running through every section. Confidence: 0.85
- **Wants the assistant to think like both a professional developer AND a design/UX expert simultaneously** when redesigning — values opinions that combine engineering tradeoffs with visual/UX judgment. Confidence: 0.8
- **Messages are often written quickly with typos, missing letters, and informal/abbreviated style** ("wiht", "thrill to the people", "m=theme", "somewher ein"). Don't correct or comment on these — interpret intent and respond normally. Confidence: 0.85
- **Requests are often bundled together in a single wall of text with multiple tasks stacked** — e.g. "put this effect in the theme, and this one somewhere in the site, and this one should be the landing page". Parse all sub-requests and address them as a single integrated plan. Confidence: 0.8
- **Projects use a Next.js + TypeScript + Tailwind stack with locally vendored ReactBits components** (no npm `reactbits` package — components live in `components/reactbits/`). Confidence: 0.95
- **Prefers adapting imported components to match the project's existing design system** (fonts, colors, gradient palettes) rather than using defaults. E.g. swapping IBM Plex Mono → JetBrains Mono, replacing default gradients with the brand orange. Confidence: 0.9
- **Prefers matching the site's monospace font (JetBrains Mono) in vendored components** by editing CSS font stacks and font-loading calls rather than loading additional Google Fonts. Confidence: 0.9
- **Brand color is `#FF4D1C` orange** with complementary tones (`#FF8C42`, `#FFB088`) and dark backgrounds (`#070707`, `#0A0A0A`, `#111827`). Use these consistently in new components. Confidence: 0.95
- **Prefers adding new packages only when strictly necessary** — first checks `package.json` and reuses existing deps (e.g. `three`, `@types/three`). Confidence: 0.9
- **Prefers plan-then-execute workflow via plan mode** for non-trivial multi-file changes, with a written plan file in `.commandcode/plans/` before code edits. Confidence: 0.85
- **Wants the assistant to discover and wire up existing-but-disconnected infrastructure** rather than rebuilding from scratch. E.g. noticed `ScrollProvider` was built but never mounted in layout, asked to wire it up instead of writing a new scroll system. Confidence: 0.8
- **Wants site-wide narrative cohesion** — prefers one cohesive transformation (e.g. scrollytelling conversion) applied across every section simultaneously with matching animation patterns, rather than piecemeal per-section updates. Confidence: 0.85
- **Values TRUE scrollytelling (Apple-style) over simple viewport-triggered fade-ins** — explicitly rejected `motion/react`'s `whileInView` pattern as "dumb" and "not scrollytelling". Wants scroll position to DIRECTLY scrub animation progress, with sections pinning in place (`pin: true, scrub: 1` in GSAP ScrollTrigger) while their internal story plays out. Confidence: 0.95
- **Explicitly names "use gsap" for scroll-driven animations** — `GSAP 3.15 + ScrollTrigger` is the chosen tool, not `motion/react` `useScroll`/`useTransform`/`whileInView`. Project already has `gsap` installed; ScrollTrigger ships with it. Confidence: 0.95
- **Prefers the `gsap.context()` cleanup pattern** wrapped around `gsap.timeline({ scrollTrigger: { trigger, start, end: '+=N', pin: true, scrub: 1 } })` with all animations inside `useEffect`, returning `ctx.revert()` for unmount cleanup. Confidence: 0.9
- **Wants scrollytelling applied holistically across EVERY major section** (Hero, Tracks, Promo, About, Prize, Timeline, Organizers, Sponsors, MagnetLines, FAQ, CTA) with the same animation pattern, not piecemeal. Each section pins for a specific `+=N` pixel range tied to its visual complexity. Confidence: 0.9
- **Values scroll-driven parallax + viewport-triggered reveals** as a baseline motion vocabulary for new sections, but only when paired with scrubbing — pure `whileInView` one-shot fade-ins are not considered sufficient for "masterpiece" sites. Confidence: 0.7
- **Wants a build verification step (`npm run build`) confirming zero new errors before declaring a multi-file task complete**. Confidence: 0.8
- **Gives blunt, direct negative feedback ("this is so dumb") when the previous work doesn't match the intended experience** — does not appreciate polished descriptions of mediocre results. Wants the assistant to acknowledge when the prior approach was fundamentally wrong (e.g. `whileInView` ≠ scrollytelling), then commit to the right tool and rewrite completely. Confidence: 0.85
- **Uses images + minimal text to communicate visual dissatisfaction** — will share a screenshot with brief commentary rather than describing what's wrong in detail. Interpret visual context + minimal text together. Confidence: 0.8
- **Strong mobile-first requirement** — explicitly asks for "very mobile friendly" sites. Expects responsive layouts across every breakpoint: smaller text, tighter spacing, mobile-specific layouts for complex visualizations (e.g. timeline stacks vertically on mobile, complex carousels get fallback card grids). Confidence: 0.9
- **Performance/lag is a top concern** — explicitly says "not laggy". Wants heavy animations gated by viewport (e.g. `gsap.matchMedia()` to skip pinning/scrubbing on mobile), `pointer-events: none` on decorative backgrounds so they don't block scroll/touch, and lightweight `scrub` values. Confidence: 0.9
- **Wants interactive effects (canvas/WebGL grids, magnet lines, etc.) used as page backgrounds with bold text overlay on top** — not as standalone sections. The interactive element is the ambient backdrop; the text/CTA is the focus. Confidence: 0.85
- **Will reject heavy pinning on every section** when it breaks layout/CSS. Prefers a hybrid approach: pin only the hero (or 1-2 hero moments) on desktop, and use normal scroll-triggered reveals (without `pin: true`) for the rest so sections stay in natural document flow. Confidence: 0.85
- **Cares deeply about the *feel* of scrollytelling pacing, not just the presence of animations** — will give follow-up feedback like "the timing flow can be improved" after the initial pass. Wants trigger windows that fire as elements ENTER the viewport (e.g. `start: 'top 80-85%'`, not `top 75%`), wider reveal windows (`end: 'bottom 20-30%'` rather than `'bottom top'`), and longer per-item stagger delays so each reveal gets its own scrolling moment. Treats these as first-class concerns, not polish. Confidence: 0.9
- **Prefers a slightly smoother scrub (e.g. `scrub: 0.8` over `scrub: 0.6`)** for cinematic feel — accepts a small trade-off in 1:1 scroll-mapping fidelity for a more luxurious, Apple-style motion feel. Avoids jarring snap. Confidence: 0.75
- **Wants UI copy to feel CREATIVE and section-specific, not templated** — rejects reused phrasing across sections (e.g. "every breakthrough has an origin" repeating the brand word). Wants each section's headline/microcopy to be tailored to that section's specific interaction (e.g. CursorGrid section → "TRACE THE GRID. IGNITE THE NETWORK." with copy that ties to the actual mechanic). Treats unique voice per section as a quality concern, not polish. Confidence: 0.9
- **For timeline / chronological sections, wants the scroll position to be meaningfully tied to the content** — milestones should reveal at their actual position along the path (mapped from x-coordinate to scroll %), with a traveling visual (e.g. orange glow, moving cursor, path draw) that gives the user a sense of "progressing through time". Wants long-form pinned scrollytelling (`pin: true, end: '+=2000', scrub: 1`) specifically for time-based storytelling, even when other sections get the lighter hybrid approach. Confidence: 0.85
- **Wants scrollytelling copy/labels to reinforce the interactive moment** — e.g. "DRAG TO REVEAL" hint, "MOVE YOUR CURSOR" prompt, "THE FIELD RESPONDS TO YOU" — microcopy that tells the user what to do and what to expect, framing the scroll as a verb/action rather than a passive event. Confidence: 0.8
